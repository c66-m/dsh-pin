# dsh-pin-running

DSH 插件：把运行中的任务置顶到侧栏顶部的独立「置顶」区。不按目录分组、不拆原文件夹；每个项目里的任务会话按最近对话时间从近到远排序；运行中绿点闪烁、自动中断/失败常亮黄、完成和用户手动停止常绿；跑完、中断或失败都继续停留，已完成项点开后切到别的任务时才移除，中断/失败项默认保留、可点 × 从置顶区移除，已完成项也可点 × 直接移除，并始终回到原会话的工作目录。另带一个独立任务监控窗口，可在 DSH 软件外显示、移动并置顶，显示任务实时状态。

## 行为

- 运行中的会话自动进入置顶区；清单由插件记在 localStorage（`dsh-pin-running.tasks.v1`），不再调用 DSH 原生 pin/unpin，原文件夹里的行保持原样。
- 运行中：绿点闪烁（脉冲）。自动中断/失败：常亮黄点，条目继续留在置顶区。跑完或用户手动停止：绿点常绿，条目继续留在置顶区。
- 点击一律用 DSH 原生 `openSession` 打开会话，会话自带原 workspace/cwd，会回到原目录。插件读取当前会话时优先使用 DSH 的实时 selection，不再把 localStorage 里的 JSON 当前会话误当裸 id；旧版遗留的裸 id 会自动修回 `{"sessionId":"..."}`。
- 同一页面只显示一个置顶区：旧热更新实例留下的置顶区会被新版样式自动隐藏，新的置顶区会标记为当前区。
- 任务监控窗口：DSH 标题栏右侧注入窗口按钮，点击打开/关闭插件自带的原生 WPF 小窗；打开时为 320×150 的任务列表，只占屏幕右上角一小块；点 － 可收成 260×38 的标题条。每行标题前显示「任务进行中 / 任务完成 / 任务中断」，这三种状态不再显示轮次、步骤等明细。
- 监控窗口通过插件 Host 路由读取任务，和侧栏置顶区共用同一份状态；只显示运行中/中断/完成的任务，运行中优先，状态随会话事件实时更新；标题前只显示任务状态标签，不再显示轮次/步骤明细。点击任务会切回 DSH 的对应会话和原目录。
- 监控窗口标题栏提供展开/收起、置顶/取消置顶、背板切换、关闭按钮；窗口可拖动，置顶状态由 📌 控制。非 Windows 平台或原生窗口启动失败时退回浏览器 `--app` 监控页。
- 背板切换：`◐` 在「透明」与「实心」之间切换，默认透明（面板 8% 黑，几乎透空）；实心为 94% 黑底。图标在透明模式下带 1px 黑色描边，保证深色/浅色桌面上都看得清。
- 点击穿透：透明/实心模式下，除标题栏（可拖动）和按钮、滚动条外，整窗 `WS_EX_TRANSPARENT` 穿透，鼠标可直接操作窗口下面的程序；轮询 25ms 根据光标位置动态切换。
- 中断/失败或已完成任务行右侧有 ×：点击只从置顶区和监控窗移除这一条壳子，不删除会话；侧栏置顶区同样可从对应行右侧 × 移除。
- 任务需要用户选择时（普通提问、审批、计划审阅），监控窗会自动弹出并把该行排到最前，显示橙色「等待回答 / 等待审批 / 计划待审」及问题摘要；点击行会打开 DSH 对应会话，在原生交互面板里作答。
- 还在运行的任务，点击只切过去查看，条目绝不移除。
- 已完成的任务，点击只是点开查看并记下「已看过」，条目仍在；等你切换到别的任务时，这个已看过且已完成的旧项才从置顶区消失。若一直不切换，它就一直留着；也可点右侧 × 立即移除置顶壳子。
- 中断/失败的任务点击后仍留在置顶区，切换到别的任务也不会消失；它们的黄点保持常亮。
- 插件加载时已经卡在 `running: true` 的旧会话同样会进入置顶区；判断运行状态以 `uiSession.sessionStatus` 为准。
- 不修改分组模式（分组/单列表由 DSH 自己决定）。唯有一项分组迁移：若检测到早期版本强制留下的 `groupBy: flat`，会切回原生文件夹分组（`workspace`）并记标记；之后用户手动选择不再干预。
- 排序：首次升级若检测到 DSH 是「手动排序」（`orderBy: manual`），会切到「最近更新」（`orderBy: updated`），每个项目里的任务按最近对话时间从近到远；之后用户仍可在 DSH 的视图菜单里手动改。
- 置顶区默认展开显示全部条目；标题始终带展开箭头，点击标题收起为只留标题，再点展开。
- 运行中的任务一旦完成/失败/中断，置顶区会自动展开，避免状态变化被收起遮住。
- 同时有多个条目时按完成 → 运行中 → 中断排序：完成的任务永远排最上面，同组按更新时间倒序；区域最高 min(40vh, 320px)，内部滚动。
- 已归档、被删、变空白或变成 subagent 的会话会自动从置顶清单里清掉，不再占 localStorage；仍在列表里的已完成项不受影响。
- 点到已不在列表的会话时，置顶区会显示一行提示（3 秒后消失），不再只写控制台。

## 实现边界

浏览器半端用 DOM 挂载到侧栏 `regionArea` 的列表上方，因为 DSH 没有暴露「会话列表顶部」的 slot。挂载点按类名的语义后缀匹配：桌面版是 `[class*="_regionArea"]` 内 `[class*="_sectionHeader"]`（「工作区」标题）之后；旧版 CLI 则退回 `.hHd-Xa_regionArea .bhn1Oq_root` 的 `listArea` 之前。任务监控窗口由 Host 半端（`index.js`）注册 `/dsh-pin-running/*` 路由，Windows 优先启动 `monitor.ps1` 原生 WPF 小窗（无 DOM 挂载点，侧栏收起或热更新不影响它），其他平台回退浏览器 `--app` 窗口。构建哈希变化不影响，只有侧栏结构大改才需要同步选择器。挂载点找不到时会在控制台警告一次，不再静默消失。

## 安装

本仓库本身就是插件源码，不是安装程序：直接下载/克隆到本地，再按下面方式引入 DSH 的插件系统即可，不需要运行安装包。文末的 `npm pack` 只是把同一份源码打成 tgz 方便离线携带，不是安装程序。

先克隆仓库（路径按你的实际位置改）：

```powershell
git clone https://github.com/c66-m/dsh-pin-running.git
```

普通 profile：

```powershell
dsh plugin --profile <name> add link:<本仓库绝对路径>
```

桌面版 profile 由 Electron 独占管理，CLI 的 `dsh plugin --profile desktop ...` 会被拒绝，需手动装：

1. 先备份 `%USERPROFILE%\.dsh\profiles\desktop\package.json`（复制一份为 `package.json.bak`），改坏可直接恢复。

2. 在 `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-pin-running` 建一个指向本仓库的 junction：

   ```powershell
   New-Item -ItemType Junction -Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-pin-running" -Target "<本仓库绝对路径>"
   ```

3. 编辑 `%USERPROFILE%\.dsh\profiles\desktop\package.json`：

   - `dependencies` 加 `"dsh-pin-running": "link:<本仓库绝对路径，正斜杠>"`
   - `dsh.profile.bundles` 末尾加 `"dsh-pin-running"`

4. 重启 DSH。

## 打包

```powershell
npm pack
```

生成 `dsh-pin-running-0.2.6.tgz`，方便离线携带分发。

卸载：删掉 package.json 里的依赖与 bundles 条目、删除 node_modules 下的 junction，重启。改坏时直接用备份的 `package.json.bak` 恢复。
